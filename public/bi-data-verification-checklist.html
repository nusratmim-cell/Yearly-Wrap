A2

Can time be split by subject?

CEO's headline ask

"Best subject / favourite subject" is the one feature the CEO named explicitly. user_activity_duration_agg has no subject column — so the only route is a join out to lessons → programs. If that join doesn't resolve to a subject, we lose the headline feature and the Focus axis with it.

-- 2a. Which join keys even exist on the agg table?
SELECT column_name FROM information_schema.columns
WHERE table_name='user_activity_duration_agg'
  AND (column_name ILIKE '%lesson%' OR column_name ILIKE '%course%'
    OR column_name ILIKE '%program%' OR column_name ILIKE '%subject%'
    OR column_name ILIKE '%content%');

-- 2b. One real student, time rolled up to subject via the join you find above.
--     Adjust the join path to the keys 2a returns. This is the proof-of-concept.
SELECT p.«subject_name», round(sum(a.«duration_sec»)/3600.0, 1) AS hours
FROM user_activity_duration_agg a
JOIN lessons  l ON l.«lesson_id»  = a.«lesson_id»
JOIN programs p ON p.«program_id» = l.«program_id»
WHERE a.«student_id» = '<pick one active student>'
  AND a.«activity_date» >= '2026-01-01'
GROUP BY 1 ORDER BY hours DESC;

Return: that one student's hours-by-subject table, and tell me the exact join path that worked. If no path reaches a subject, say so plainly — that single sentence rewrites the spec.

A3

2026 coverage — is the full year actually there?

silent-gap check

The table went live 2024-11-03, so 2026 should be complete. But a 3-week pipeline outage in, say, April would make every streak and every total wrong for whoever studied then — and nobody would notice until a student screenshots a broken number.

-- Rows, distinct students, and days-present per month. days_present must
-- equal the number of days in that month (28/30/31). A short month = a gap.
SELECT date_trunc('month', «activity_date») AS mon,
       count(*) AS rows,
       count(DISTINCT «student_id») AS students,
       count(DISTINCT «activity_date») AS days_present
FROM user_activity_duration_agg
WHERE «activity_date» >= '2026-01-01' AND «activity_date» < '2027-01-01'
GROUP BY 1 ORDER BY 1;

Return: the 12-row table. Flag any month where days_present < calendar days, or where rows/students drop off a cliff versus neighbours.

A4

How many of the paid cohort can even get a real Wrap?

sizes the fallback

If 28k are targeted but only 11k studied enough to fill a Wrap, we're really building two products: the full Wrap, and a "Fresh Start" fallback for the quiet 17k. We need the real split now to know which one carries the launch.

-- Define the cohort ONCE. Match ST-25781's paid scoping (by program/phase).
-- Confirm the paid definition with the ST-25781 author; adjust columns.
CREATE TEMP VIEW wrap_cohort AS
SELECT DISTINCT s.«student_id»
FROM "Students" s
JOIN "Transactions" t ON t.«student_id» = s.«student_id»
WHERE t.«status» = 'paid'                      -- confirm enum value
  AND t.«paid_at» >= '2026-01-01' AND t.«paid_at» < '2027-01-01';

-- Histogram: active days in 2026 per paid student.
WITH per_student AS (
  SELECT a.«student_id», count(DISTINCT a.«activity_date») AS active_days
  FROM user_activity_duration_agg a
  JOIN wrap_cohort c ON c.«student_id» = a.«student_id»
  WHERE a.«activity_date» >= '2026-01-01' AND a.«activity_date» < '2027-01-01'
  GROUP BY 1)
SELECT CASE
         WHEN active_days < 5   THEN '0–4 (Fresh Start)'
         WHEN active_days < 20  THEN '5–19'
         WHEN active_days < 50  THEN '20–49'
         WHEN active_days < 150 THEN '50–149'
         ELSE '150+' END AS band,
       count(*) AS students
FROM per_student GROUP BY 1 ORDER BY 1;

-- And the headline number: paid students with ZERO activity rows in 2026.
SELECT count(*) FROM wrap_cohort c
WHERE NOT EXISTS (SELECT 1 FROM user_activity_duration_agg a
  WHERE a.«student_id»=c.«student_id» AND a.«activity_date» >= '2026-01-01');

Return: the 5-band histogram + the total cohort size + the zero-activity count. That tells me the real denominator for everything below.

B1

The four personality axes — run them, return the split

kills dead axes

An axis where everyone lands on one side is not an axis — it's a constant. Any axis that comes back past ~85/15 gets dropped, because it adds a slide that says the same thing to everyone.

-- RHYTHM — Regular vs Sporadic. Regular = ≥3 active days per enrolled week.
-- weeks_enrolled = weeks between the student's first 2026 activity and 31 Dec.
WITH s AS (
  SELECT a.«student_id»,
    count(DISTINCT a.«activity_date») AS active_days,
    greatest(1, ('2026-12-31'::date - min(a.«activity_date»)::date)/7.0) AS weeks_enrolled
  FROM user_activity_duration_agg a JOIN wrap_cohort c USING («student_id»)
  WHERE a.«activity_date» >= '2026-01-01' GROUP BY 1)
SELECT (active_days/weeks_enrolled >= 3.0) AS is_regular, count(*)
FROM s GROUP BY 1;

-- CLOCK — Owl vs Lark. Needs the time-of-day column from A1 («hour»).
-- Owl = ≥50% of study seconds in evening(18–23) + after-midnight(0–4).
WITH s AS (
  SELECT «student_id»,
    sum(CASE WHEN «hour» >= 18 OR «hour» < 5 THEN «duration_sec» ELSE 0 END)::numeric
      / nullif(sum(«duration_sec»),0) AS night_share
  FROM user_activity_duration_agg a JOIN wrap_cohort c USING («student_id»)
  WHERE a.«activity_date» >= '2026-01-01' GROUP BY 1)
SELECT (night_share >= 0.50) AS is_owl, count(*) FROM s GROUP BY 1;

-- METHOD — Doer vs Viewer. Needs the activity-type column from A1.
-- Doer = ≥50% of seconds in active types (mcq/practice/quiz) vs video.
WITH s AS (
  SELECT «student_id»,
    sum(CASE WHEN «activity_type» IN ('mcq','practice','quiz') THEN «duration_sec» ELSE 0 END)::numeric
      / nullif(sum(«duration_sec»),0) AS active_share   -- confirm enum values!
  FROM user_activity_duration_agg a JOIN wrap_cohort c USING («student_id»)
  WHERE a.«activity_date» >= '2026-01-01' GROUP BY 1)
SELECT (active_share >= 0.50) AS is_doer, count(*) FROM s GROUP BY 1;

-- FOCUS — Focused vs Explorer. Needs the A2 subject join.
-- Focused = top subject is ≥40% of total study time.
WITH bysub AS (
  SELECT a.«student_id», p.«subject_name», sum(a.«duration_sec») AS sec
  FROM user_activity_duration_agg a JOIN wrap_cohort c USING («student_id»)
  JOIN lessons l ON l.«lesson_id»=a.«lesson_id»
  JOIN programs p ON p.«program_id»=l.«program_id»
  WHERE a.«activity_date» >= '2026-01-01' GROUP BY 1,2),
s AS (SELECT «student_id», max(sec)::numeric/nullif(sum(sec),0) AS top_share
     FROM bysub GROUP BY 1)
SELECT (top_share >= 0.40) AS is_focused, count(*) FROM s GROUP BY 1;

Return: the four two-row splits. For any axis past 85/15, say so — I'll drop it rather than tune it.

The 16-type crosstab — the number that decides everything

-- Combine the four booleans from B1 into one flag per student, then count

D1

guardrail
-- Template — run per metric (total study hours, live-class count,
-- quiz accuracy, longest streak, final score). Swap the expression + source.
SELECT
  count(*)                                              AS n,
  round(100.0*count(*) FILTER (WHERE «metric» IS NULL)/count(*),1) AS null_pct,
  min(«metric»),
  percentile_cont(0.50) WITHIN GROUP (ORDER BY «metric») AS median,
  percentile_cont(0.95) WITHIN GROUP (ORDER BY «metric») AS p95,
  max(«metric»)
FROM ( /* per-student rollup of the metric, joined to wrap_cohort */ ) q;

Return: one row per metric. I'm hunting for impossible maxes (negative time, >24h/day, accuracy >100%) and high null-rates that would blank a card.
