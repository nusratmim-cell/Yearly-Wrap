00Thesis & the principles we build against

Wrapped is not a stats screen — it's an identity product with a growth loop attached. It takes raw behaviour, derives something that feels like a truth about you, gives you a word for it, and hands you a card built to be shared. The numbers are raw material. Over four years Spotify moved steadily from "here are your numbers" to "here is who you are." That vector is the entire lesson.

The designs look initially nice but we are mostly representing user data attractively. Let's go a step deeper… Spotify Wrapped generates insights based on the individual… My experience would be — wow, I learned something new about myself… for 20 to 30 thousand students, make it as unique as possible for each. — Ishmam Ahmed Chowdhury, CEO

North-star sentence: a student finishes the Wrap and thinks "that's so me" — then sends it to a friend to prove it. The seven principles below are the lens; every feature in this spec is tagged to them.

1
Stats are the floor; identity is the ceiling. Nobody shares "142 hours." They share "I'm a Night-Owl Specialist." Numbers earn trust; the label gets shared.
2
Derive, don't display. Every memorable feature is computed, not shown. The product is the function that turns 5 numbers into 1 meaning.
3
Variable slides = uniqueness. Slides are gated by eligibility; the set differs per student. Our current prototype's fixed order is the single biggest thing to fix.
4
Give people a word for themselves. Archetypes are identity + language + inherently social. People love a flattering category.
5
Engineer one "how did it know that?" moment — a cross-signal revelation the user never stated. This is the CEO's ask, literally.
6
Design the share, not just the screen. The share card is the cheapest acquisition channel to reach 30k students' friends.
7
Close with forward motion. End by pulling the student back in January — that's literally our return-rate metric.

02The Learner Personality system — axes & math

Our answer to Listening Personality, and the finale the whole wrap builds toward. The discipline that keeps it rigorous (and tunable as settings): define 4 binary axes on real data first; the 16 types fall out of the combinations. Never invent 16 vague labels and reverse-engineer.

The four axes

Rhythm
R ↔ S
Regular (R) vs Sporadic (S) — how consistently they showed up.
metric = active_days / weeks_enrolled from user_activity_duration_agg.activity_date. Threshold (setting): ≥ 3.0 active days/week → R, else S. Streak length is a tiebreaker.
Clock
O ↔ L
Owl (O) vs Lark (L) — when they studied.
metric = (evening + after_midnight) / total study time from datafuse.user_activity_agg bands. Threshold: ≥ 0.50 → O, else L.
Method
D ↔ V
Doer (D) vs Viewer (V) — practice vs passive consumption.
metric = active_time / (active_time + video_time), where active = quiz + live-exam + model-test + live-class durations, video = recorded + animated. From user_activity_duration_agg. Threshold: ≥ 0.50 → D, else V.
Focus
F ↔ E
Focused (F) vs Explorer (E) — depth in one subject vs breadth.
metric = top_subject_time / total_subject_time (Herfindahl concentration as alt). From the subject-time reconstruction. Threshold: top subject ≥ 40% of study time → F, else E.
Data dependency: Focus and the subject cards depend on subject-level study time, which the main agg table does not carry — it's reconstructed from watch_logs / student_attendees↔lessons / mcq_user_chapter_daily and must be reconciled with BI. Clock depends on confirming the user_activity_agg hour bands. Both are the gating unknowns for this system.
Code & assignment: each student gets a 4-letter code like R-O-D-F. For students near a threshold (within a configurable band), store the second-nearest type too, so copy can hedge ("you're a Night Owl, with a touch of Explorer"). Low-activity students (below the wrap's minimum-activity gate) bypass the 16 and get the dedicated নতুন শুরু ("Fresh Start") type.

05The selection & ordering engine

Given one student's record and the library, emit a unique ordered list. This is the core of "unique for each of 30k." Runs in the nightly job; output is stored in the student's Wrap record so the API just reads it.

Scoring

For each eligible card, interestingness ∈ [0,1]:

# per candidate card c for student s
score(s,c) = w_extreme · extremity(s,c)      # how far from the typical student (needs BI distributions)
           + w_rare    · rarity(c)            # how few students qualify for c at all
           + w_ceo     · ceo_priority(c)      # favourite teacher, best-exam-subject get a bump
           + w_combo   · is_combination(c)    # reward cross-signal "wow" cards
           − w_fatigue · category_seen(c)     # penalise a category already picked

extremity(s,c) = |percentile(s.value_c) − 0.5| · 2   # 0 = average, 1 = extreme either way

Selection & ordering

# 1. eligibility
candidates = [c for c in LIBRARY if c.gate(s)]

# 2. fixed anchors
opener   = pick(["active_days","total_hours"])        # warm, universal
finale   = "learner_personality"                       # always the reveal
closer   = "2027_study_plan" -> "share_card"           # forward motion + share
game     = "two_truths_lie" if len(strong_cards)>=4    # optional delight, mid-wrap

# 3. body: top scorers with variety
body = []
for c in sorted(candidates, by=score, desc):
    if c in (opener,finale) : continue
    if category_count(body, c.category) >= 1 : continue   # max 1 per category
    body.append(c)
    if len(body) >= target_len(s) : break                  # target 7–10 by data richness

# 4. order on a drama curve
wrap = [opener]
    + sort_ascending_by_score(body[: -2])   # build up
    + highest_scoring_combo(body)           # the "how did it know" beat, late
    + [game]                                # breath / delight
    + [finale]                              # personality reveal (door opens)
    + [closer...]                           # plan + share

# 5. guarantee
if len(wrap) < MIN_LEN:  wrap += fallback_pool(s)   # course bought, upcoming classes, gentle stat

Variety rule

Max one card per category in the body, so no three subject cards in a row. Categories: effort, identity, revelation, loyalty.

Drama curve

Warm open → ascending interest → the combination "wow" late → personality reveal → forward close. Not strict ascending; the combo and finale are placed, not sorted.

Never-empty

MIN_LEN guaranteed for every student. Light users fall through to Fresh Start + course + upcoming-2027-classes. No hollow wraps.

Why this lives in the batch job, not the app: the ordered list is computed once per student and stored. The API returns it; the web story renders it. Product retunes weights/thresholds as settings — no app release. This is exactly the "tiers are settings" requirement from SC-1737, extended to selection.

06Signature feature specs (v1)

Spotify is remembered for 2–3 signature slides a year. Here are our five, each as a mini-spec: user story, inputs, computation, copy rules, edge cases, effort. Everything else (Aura, Study Twin, AI podcast, Blend) is v2 backlog.

S1 · শিখো Learner Personality  BUILD

Story: "As a student, I want a name for how I learned this year, so I feel seen and can share it."

  • Inputs: the four axis metrics (§2).
  • Compute: threshold each axis → 4-letter code → map to type + copy; store nearest-neighbour type for hedging.
  • Layout: reveal interaction (door/flip), type name + illustration + the axis bars that produced it ("here's why").
  • Copy: headline + body + share line per type (§3).
  • Edge: below activity gate → Fresh Start; near a threshold → "with a touch of…".
  • Effort: M (needs subject-time + time-bands ready).

S2 · তোমার পড়ার দিন (your study day)  BUILD

Story: "Show me when I study and what — I didn't realise I'm a night person for Physics."

  • Inputs: time-of-day bands (user_activity_agg), subject×time-band.
  • Compute: % per band; for the top 1–2 subjects, the band where each peaks.
  • Layout: a 24h ribbon/clock, subjects pinned to their peak band.
  • Edge: if bands are flat (no clear peak) → fall back to simple night/day split; needs the user_activity_agg band-hours confirmed.
  • Effort: M.

S3 · তোমার ২০২৬ এর অধ্যায় (year in phases)  BUILD

Story: "Tell my year as a story with chapters, not a flat total."

  • Inputs: monthly study time, monthly accuracy, monthly dominant subject.
  • Compute: segment 12 months into 2–3 phases by change-points (e.g. activity level shift); name each by its dominant behaviour ("slow start", "the grind", "exam sprint").
  • Layout: a timeline with named phases; tap a phase for its stats.
  • Edge: single-phase programs (one quarter) → a single "snapshot" chapter (mirrors the 2025 PRD's single-phase handling).
  • Effort: M–L (segmentation logic).

S4 · দুটো সত্যি, একটা মিথ্যা (2 truths & a lie)  BUILD

Story: "Make me interact — quiz me on my own year."

  • Inputs: the student's top 3 true facts (from selected cards).
  • Compute: synth one false-but-plausible fact (perturb a real value within a believable band; never a value that could embarrass).
  • Layout: 3 tappable cards → reveal correct/incorrect with a smile.
  • Edge: <4 strong cards → skip (gate). Ensure the lie is never accidentally true.
  • Effort: S–M. High delight-per-effort.

S5 · ২০২৭ স্টাডি প্ল্যান (the return hook)  BUILD

Story: "Now that I've seen 2026, tell me what to do in January" — this is our return-rate metric.

  • Inputs: weakest 1–2 subjects/chapters (accuracy), upcoming 2027 classes (lessons), opportunity subject.
  • Compute: Gen-AI (or rules) → 2–3 concrete next steps + a deep link into the app.
  • Layout: checklist + CTA "২০২৭ শুরু করো".
  • Edge: if 2027 schedule isn't in lessons by cut-off → generic plan + course CTA.
  • Effort: M. Owns the January return loop.

Plus the floor (core stat cards) and the two CEO asks (favourite teacher, best exam subject). That's a complete, shippable v1 that feels like Wrapped without 20 slides.

(From SC-1737; targets TBD.) Beyond the funnel, instrument the engine itself:

  • Per-card analytics: impressions, dwell time, drop-off, share-from-card. Tells us which cards earn their slot — feeds next year's library pruning.
  • Personality distribution: are the 16 types balanced? Near-empty types → merge an axis (settings change).
  • Experiments: (a) personality finale ON vs OFF → share rate; (b) 2027-plan close ON vs OFF → January return (the money metric); (c) engine-selected variable order vs fixed order → finish + share. These validate that the insight engine actually beats "pretty data".
  • Guardrail: finish rate for low-activity students (the fallback path) — must not crater.
